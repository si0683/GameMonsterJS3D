# AGENTS.md — rules for AI coding agents

GameMonsterJS3D is a **project starter**: the npm package `create-gamemonsterjs3d` copies `template/` (Vite + React + Three.js + React Three Fiber + Drei + React Three Rapier + Howler.js + zustand + TypeScript) into a new folder and runs `npm install`.

- `bin/create.mjs` — the CLI, Node ≥ 20.19, no dependencies (same code as GameMonsterJS2D, different constants at the top). The template keeps `.gitignore` as `template/_gitignore`; the CLI renames it.
- `template/` — a working game. Work on it in place: `cd template && npm install && npm run dev`. `template/AGENTS.md` is the guide for agents in the user's project — keep it in sync.
- Assets: only CC0 or own work; list every file in `template/public/CREDITS.md`. `models/tree.glb` was generated with three.js GLTFExporter.
- Player texts Russian, code comments English.
- Before a release: `npm pack`, `npx ./create-gamemonsterjs3d-<v>.tgz "Test Game"` in a temp folder, `npm run build` there, play it in `npm run dev` (keyboard and touch; `window.useGame` and `window.player` help to script a test), no console errors. Keep the browser tab in the foreground — hidden tabs throttle `requestAnimationFrame` and physics looks frozen.
- Versions: `version` in package.json + CHANGELOG.md + tag `vX.Y.Z`; published tags are never changed.
- `index.html` in the root is the GitHub Pages page: only a short install guide, one screen, Inter font, light/dark theme.
- `PROMT.md` (Russian fill-in brief for AI assistants) lives in the root for download and as `template/PROMT.md` in every new project — keep both copies identical and in sync with the template (stack, scripts, file names).
- Platform SDKs: the game calls only `platform` from `template/src/platform/` (interface `types.ts`, no-SDK implementation `none.ts`, `index.ts` picks one). Each SDK lives in `sdks/<name>/`: `sdk.json` (title, package scripts/dependencies merged into the project, list of docs to append), `files/` (copied over the template: `src/platform/<name>.ts`, an `index.ts` that exports it, its docs) and `append/` (text added to the end of AGENTS.md, README.md, PROMT.md). `bin/create.mjs` lists `sdks/` automatically for `--sdk=<name>` and the interactive question.
- Views: `views/<name>/` = `view.json` (title, package dependencies, `remove` — template files to delete, `append` — docs to extend) + `files/` (copied over the template) + `append/`. `--view=third` is the template itself; `--view=first` (first-person horror: grid maze, pointer lock, flashlight, @react-three/postprocessing, a path-finding creature) replaces `src/App.tsx`, `config.ts`, `rules.ts`, `store.ts`, `i18n.ts`, `ui/*`, `e2e/game.spec.ts` and adds `src/game/*`, `input.ts`, `firstperson.css`. The installer applies the view before the SDK. A view must keep the store API that `main.tsx` uses (`best`, `settings`, `noAds`, `pause`, `resume`) and pass `npm run check` + `npm run test:e2e` with every SDK.
- Adding an SDK (VK Play, CrazyGames, Poki…): new `sdks/<name>/` with the same layout; implement every `Platform` method (fall back to `none.ts` when the SDK script is missing so `npm run dev` keeps working); a new method goes to `types.ts` + `none.ts` + every SDK. Both GameMonsterJS2D and GameMonsterJS3D share the same `src/platform/*` and `sdks/yandex/files/src/platform/*` files — keep them identical.
- Release check for SDKs: create a project for every `--sdk` value and build it; test `yandex` with the real dev SDK (`npm run yandex`, or serve `dist/` with the proxied `/sdk.js` next to it): LoadingAPI.ready, GameplayAPI start/stop, fullscreen ad open/close with pause/resume, setData, setScore.
